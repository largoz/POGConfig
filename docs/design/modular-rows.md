# POG Config: модульні рядки, вибір зі списку, масштаб — чернетка дизайну

Стан: **чернетка на погодження**, коду ще немає. Після погодження з неї виростуть код і нова вікі
(англійською, для розробників модів).

## 1. Що хочемо і чого не ламаємо

Хочемо:
- **Модульність.** Кожен рядок налаштувань — це компонент плюс довільний набір модулів. Без рівнів і
  без обов'язкового порядку: розробник бере лише те, що йому треба.
- **Найпростіший випадок — один рядок коду.** Хто хоче просто список, пише список і все.
- **Шпаргалка.** Для кожного компонента відомо, які модулі до нього застосовні, і це перевіряє
  компілятор: модуль, що не пасує до компонента, просто не скомпілюється.
- **Вибір зі списку** з пошуком і фільтрами, що витримує тисячі пунктів.
- **Більше вікно і шрифт** з самого початку — і **одна точка масштабу**, щоб потім додати повзунок
  «Масштаб інтерфейсу» без переписування.
- **Власні компоненти й модулі** від інших розробників (зараз це неможливо: внутрішні методи закриті).
- **Відкритість без привілейованого ядра.** Вбудовані компоненти й модулі написані тим самим
  публічним API, що й сторонні: POG Config не має «внутрішніх» можливостей, недоступних іншим. Те, що
  вміє наш повзунок, може повторити чужий компонент, а чужий модуль може причепитися до нашого повзунка.

Не ламаємо: усе, чим користуються вже опубліковані моди (§9).

## 2. Три шари

| Шар | Що це | Хто з ним працює |
|---|---|---|
| **Компонент** (тип рядка) | що за налаштування: перемикач, повзунок, вибір, клавіша, кнопка, заголовок | розробник мода — завжди |
| **Модулі** | додаткові можливості рядка: збереження, підказка, пошук, фільтри, формат, кроки, умова видимості… | розробник мода — за потреби |
| **Тема і масштаб** | розміри вікна, рядків, кеглі шрифтів, один множник масштабу | POG Config сам; власні компоненти беруть розміри з теми |

## 3. Як це виглядає в коді

Найпростіше — нічого зайвого:

```csharp
POGConfig.Register("My Mod", new List<ConfigEntry>
{
    new HeaderRow("General"),
    new ToggleRow("Enabled", () => _on, v => _on = v),
    new ChoiceRow("Difficulty", () => _diff, v => _diff = v, "Easy", "Normal", "Hard"),
});
```

З модулями — ланцюжком, кожен модуль одним викликом:

```csharp
new SliderRow("Volume", () => _vol, v => _vol = v, 0f, 1f)
    .Saved("Volume")                 // зберігати між запусками
    .Format(v => $"{v * 100:F0}%")   // як показувати значення
    .Steps(11)                       // 11 позначок на доріжці
    .Tooltip("Master volume of the mod's sounds"),

new ChoiceRow("Menu font", () => _font, v => _font = v, FontOptions)
    .Saved("MenuFont")
    .Searchable()                    // поле пошуку в списку
    .Filters("Font mods", "Game fonts"),  // кнопки-фільтри за мітками пунктів
```

Модулі незалежні: їх можна додати в будь-якій кількості й будь-якому порядку. `Steps` до
`ChoiceRow` не пасує — і не скомпілюється (§5).

Назви з суфіксом `Row`, щоб не зіткнутися з `UnityEngine.UI.Toggle`/`Slider`, які в модах часто
підключені через `using`.

## 4. Компоненти

| Компонент | Значення | Вигляд | Заміняє (1.x) |
|---|---|---|---|
| `HeaderRow` | — | заголовок розділу | `HeaderEntry` |
| `ToggleRow` | `bool` | перемикач | `ToggleEntry` |
| `SliderRow` | `float` | повзунок + поле для числа | `SliderEntry` |
| `ChoiceRow` | ключ вибраного пункту (`string`) | кнопка → **список** (за замовчуванням) або повзунок `.AsSlider()` | `OptionsSliderEntry` |
| `KeyRow` | `KeyCode` (1–3 слоти) | слоти клавіш | `KeyEntry` |
| `ButtonRow` | — | кнопка з дією | `ButtonEntry` |
| `TextRow` (згодом) | `string` | поле вводу | — |
| `CustomRow` | будь-яке | що побудує розробник | (не було) |

**`ChoiceRow` зберігає ключ пункту, а не його номер.** Урок POG Fonts: коли список міняється
(додали шрифт), номер вказує вже на інший пункт, а ключ — ні. Пункти можна задати рядками
(ключ = підпис) або об'єктами:

```csharp
new Option("goblin-menu", "Goblin Menu (Cyrillic)") { Tags = { "Font mods" }, Description = "…" }
```

і списком, який міняється під час гри: `() => CurrentOptions()` — тоді не треба перереєстровувати
сторінку, як зараз робить POG Fonts.

## 5. Модулі і шпаргалка

### 5.1 Приклад: з чого складається повзунок

Зараз усе це — параметри одного конструктора `SliderEntry(label, get, set, min, max, fmt, prefKey,
originValue, showFill, wholeNumbers, stepPointsCount)`: поєднувати можна, але позиційно (`null, 0f,
true, false, 9`), опису немає, поле з цифрами не вимкнути. Стане:

```
[ Підпис              ] [ 43s ] [====|========•====•====•====]
[ Опис дрібним шрифтом]   цифри   заливка від центру, поінти
```

| Частина повзунка | Модуль | Зараз (1.x) |
|---|---|---|
| поінти на доріжці | `.Steps(n)` | `stepPointsCount` |
| центрування: заливка від точки, напр. від 0 у діапазоні −50…50 | `.Fill(origin)` | `originValue` |
| без заливки | `.NoFill()` | `showFill: false` |
| цифри: поле зі значенням, можна вписати число | `.Numbers()` (увімкнено за замовчуванням), `.Numbers(false)` | завжди увімкнено |
| як показувати цифри (`43s`, `80%`) | `.Format(v => …)` | `fmt` |
| лише цілі | `.WholeNumbers()` | `wholeNumbers` |
| опис під підписом | `.Description(text)` | немає |
| підказка при наведенні | `.Tooltip(text)` | немає |
| кнопка «скинути цей рядок» | `.ResetButton()` | немає |
| збереження | `.Saved(key)` | `prefKey` |
| частки ширини | `.Layout(label, value)` | `LabelFraction`, `ValueFraction` |

Будь-яку підмножину можна поєднати, порядок не важливий.

### 5.2 Модулі чіпляються за можливістю, а не за типом рядка

Кожен компонент оголошує свої **можливості**, кожен модуль — що йому **потрібно**:

| Можливість | Що означає | Мають |
|---|---|---|
| `ILabeled` | є підпис | усі |
| `IValue<T>` | є значення типу `T` (читання/запис) | Toggle (`bool`), Slider (`float`), Choice (`string`), Key (`KeyCode`), Text (`string`) |
| `INumeric` | значення — число з діапазоном | Slider |
| `IOptions` | значення вибирається з пунктів | Choice |
| `IKeySlots` | слоти клавіш | Key |
| `IAction` | рядок виконує дію | Button |

| Модуль | Потребує | Отже працює з |
|---|---|---|
| `.Description`, `.Tooltip`, `.VisibleIf`, `.Layout` | `ILabeled` | усіма |
| `.Saved`, `.OnChanged`, `.EnabledIf`, `.ResetButton` | `IValue<T>` | Toggle, Slider, Choice, Key, Text |
| `.Steps`, `.Fill`, `.NoFill`, `.Numbers`, `.Format`, `.WholeNumbers` | `INumeric` | Slider |
| `.Searchable`, `.Filters`, `.Groups`, `.AsSlider` | `IOptions` | Choice |
| `.Slots`, `.KeyboardOnly` | `IKeySlots` | Key |
| `.Confirm` | `IAction` | Button |

Наслідки:
- **Компілятор тримає шпаргалку чесною**: модуль оголошено як розширення лише для типів з потрібною
  можливістю, тож `.Steps()` на перемикачі не скомпілюється, а автодоповнення після крапки показує
  рівно ті модулі, що підходять.
- **Чужий компонент отримує готові модулі задарма**: хто зробить, скажімо, `RangeRow` (два повзунки
  min–max) і оголосить `INumeric`, отримає `.Steps`, `.Format`, `.Numbers` без жодного рядка коду.
- **Чужий модуль працює з нашими компонентами**: модуль «кольоровий зразок» з вимогою `IValue<float>`
  одразу пасує до повзунка.
- **Шпаргалка у вікі генерується з коду** (можливості й вимоги оголошені в коді), тож не розійдеться
  з реальністю.

## 6. Вибір зі списку

- Рядок показує вибраний пункт. Клік відкриває список поверх сторінки (не окреме вікно).
- Угорі поле пошуку (якщо `.Searchable()` або 10+ пунктів): фільтрує на льоту, без урахування регістру,
  по підпису й міткам. Набір тексту одразу йде в пошук.
- Під пошуком — кнопки-фільтри (`.Filters`), можна кілька разом.
- Список **малює лише видимі пункти**, тож тисячі пунктів не гальмують.
- Клавіатура: стрілки, Enter — вибрати, Esc — закрити без змін. Мишка: клік, колесо.
- Вибраний пункт підсвічено, список відкривається прокрученим до нього.
- Esc поводиться як зараз: спершу закриває список/пошук, лише потім панель.

## 7. Один вигляд і масштаб

Зараз панель 980×600 на віртуальному полотні 1920×1080, кеглі 10–22 розкидані числами по коду, тож
на 1366×768 підписи ≈10 px.

**Масштаб — один множник.** Уся панель будується в одиницях полотна, тож множник ділить опорну
роздільність полотна (1920×1080 / `Scale`): зростає все разом, вікно й шрифти, без правки чисел у
коді. За замовчуванням `Scale = 1.35`, панель 1040×650 одиниць → на 1366×768 ≈ 73% × 80% екрана.
Значення — у `UserData/MelonPreferences.cfg`, `[POG_Config] UIScale`, діє одразу; повзунок «Масштаб
інтерфейсу» — окремим кроком.

**Один вигляд для всіх модів** (рішення користувача, 2026-11-11). Розміри й кольори панелі однакові на
сторінці кожного мода: мод не задає своїх розмірів, кеглів чи кольорів ні для сторінки, ні для типу
рядка, ні для окремого рядка. Міняє вигляд лише гравець, і лише весь разом — масштабом, як масштаб
сторінки в браузері. Так налаштування різних модів виглядають однорідно, а гравець одним числом
підганяє все під свій екран.

Розміри — іменовані властивості (`font-size-label`, `row-height`, `header-height`…) в одному місці,
`Theme.Defaults`, замість чисел по коду. Це не каскад для модів, а спільний словник, щоб усі
компоненти, і вбудовані, і власні (§8), брали ті самі числа. Розміри задаються в одиницях до множника
масштабу, тож `Scale` діє на все однаково. Компоненти питають `Theme`, а не мають своїх чисел.

Раніше тут був каскад із п'яти рівнів, як у CSS (стандарт → гравець → сторінка мода → тип рядка →
рядок). Рівні 3–5 скасовано: вони дозволили б кожному моду мати свій вигляд.

## 8. Власні компоненти і модулі

Те саме API, яким зроблено вбудовані:
- **Компонент**: клас, що будує рядок через `RowBuilder` (підпис, текст значення, кнопка, доріжка,
  обробник кліку, розміри з теми) і оголошує свої можливості (§5.2). Усі модулі з потрібними
  можливостями з ним працюють.
- **Модуль**: клас `IRowModule<in TCapability>` з точками входу: побудова рядка (додати свій
  елемент), оновлення кожен кадр, зміна значення, збереження/відновлення, скидання до
  замовчування. Плюс метод-розширення для зручного виклику (`.MyModule()`).
- **Реєстр модулів** відкритий: інший мод може постачати модулі як бібліотеку (окремий пакет на
  Thunderstore), а моди-користувачі — підключати їх так само, як вбудовані.
- Помилка в чужому модулі не валить панель: модуль вимикається з одним рядком у лог (як зараз з
  рядками, що кидають виняток).

## 9. Сумісність зі старими типами

Опубліковані моди, що залежать від POG Config:

| Мод | Що використовує |
|---|---|
| GoblinOverheadHUD 1.0.1 (GlitchApotamus) | `ToggleEntry`, `OptionsSliderEntry`, напряму |
| POGPOVChanger 1.0.2 (GlitchApotamus) | `KeyEntry` **через рефлексію**: шукає клас за назвою і конструктор за точними параметрами |
| POG BrightMod 4.1.0, POG Fonts (твої) | `OptionsSliderEntry` та ін. |

Тому:
1. **Старі класи лишаються** з тими самими назвами, конструкторами (до параметра) і властивостями
   (`LabelFraction`, `ValueFraction`, `AllowMouseButtons`). Збережені значення — у тих самих
   ключах і типах (`OptionsSliderEntry` і далі зберігає номер).
2. **Всередині вони — набори модулів** над новими компонентами: `OptionsSliderEntry` =
   `ChoiceRow` за номером + `.AsSlider()`; `KeyEntry` = `KeyRow` + `.Slots(n)`. Окремої старої
   реалізації не лишається.
3. **`[Obsolete]`** на старих класах: розробник бачить попередження під час збирання свого мода.
   Гравець — ні.
4. **Один рядок у консоль на мод** при реєстрації: «'GoblinOverheadHUD' uses POG Config 1.x rows
   (ToggleEntry, OptionsSliderEntry); they keep working. New rows: wiki → Migrating from 1.x».
   Без повторів.
5. **Вікі** описує лише нові компоненти; окрема сторінка «Migrating from 1.x» з відповідністю
   «старий запис → новий».
6. **PR для GlitchApotamus** з переходом на нові рядки — коли нове вийде.
7. **Коли прибрати старе**: у наступній мажорній версії (2.0.0) і лише коли всі відомі залежні моди
   перейшли. До того старі класи не міняються.
8. **Тест на сумісність** (обов'язково, до випуску): зібрати GoblinOverheadHUD і POV Changer як є
   (опубліковані DLL) проти нового POG Config і перевірити в грі, що їхні рядки на місці.

## 10. Версії і порядок робіт

Новий API нічого не ламає, тож це **1.1.0** (старе лише позначене застарілим); прибирання старого —
2.0.0.

| Крок | Що | Перевіряємо |
|---|---|---|
| 1 | Масштаб (множник полотна) + більша панель; розміри в `Theme.Defaults` | скріншоти до/після на 1366×768 |
| 2 | Ядро компонентів і модулів; старі класи стають наборами модулів | опубліковані GoblinOverheadHUD і POV Changer працюють без змін |
| 3 | `ChoiceRow` зі списком, пошуком, фільтрами, віртуалізацією | тестовий мод із 5 000 пунктами; клавіатура; Esc |
| 4 | `CustomRow`, свої модулі; `[Obsolete]`; рядок у консоль | тестовий сторонній модуль |
| 5 | Вікі: нові сторінки, шпаргалка, міграція | — |
| 6 | POG Fonts переходить на `ChoiceRow` (пошук, фільтри «Font mods / Game fonts») | у грі |

## 11. Питання до тебе

1. Назви компонентів з суфіксом `Row` (`ToggleRow`, `ChoiceRow`…) — ок? Альтернатива: фабрика
   `Rows.Toggle(...)`.
2. Розмір панелі за замовчуванням: ≈86% екрана — ок, чи інакше?
3. Повзунок «Масштаб інтерфейсу» — пізніше, як ти казав, чи одразу з кроком 1?
4. Список відкривається поверх сторінки (як випадне вікно в межах панелі) — ок?
5. Версія 1.1.0 для нового API — чи хочеш 2.0.0, щоб підкреслити зміну (тоді прибирання старого — 3.0.0)?
6. Чого ще бракує в розбивці повзунка (§5.1)? Ти казав «що щось» — можливо, підписи min/max на кінцях
   доріжки, крок колеса миші, «прилипання» до поінтів?
